# エッジAI設計

この文書には、エッジAIに必要な設計上の固定契約を置く。現在は音響特徴量とCPU間状態語を対象とし、将来のモデル、特徴量、通信に関する設計判断もここへ集約する。

最終更新: 2026-09-11

この文書は、音響特徴量、ESP32S3–CPU0間プロトコル、CPU0–CPU1状態語の
実装が共有する固定契約をまとめたものです。実装の進捗や作業順とは独立した
設計資料として扱います。ここに記載した値を変更する場合は、送受信両端、
ホスト参照実装、テスト、学習済みモデルへの影響を確認してから変更します。

## 音響特徴量

| 項目 | 固定値 |
|---|---|
| 入力 | 16 kHz / mono。XVF3800処理済みI2Sの1チャンネル |
| 窓 | 400 samples（25 ms） |
| FFT | 512 points。400 samplesの後ろを0埋め。片側257 bins、bin間隔31.25 Hz |
| ホップ | 160 samples（10 ms、100 frames/s） |
| 窓関数 | Hann |
| melフィルタ | 32 bins、下端125 Hz |
| フレーム量子化 | int8、1フレーム32 bytes |
| レベル処理 | 各フレームの対数エネルギー平均を減算するレベル正規化 |
| イベント | 前300 ms＋後500 ms、合計800 ms＝80 frames |

I2Sの読み出し単位は256 samplesなので、160-sample hopと一致しません。
フレーム生成器は読み出し境界をまたぐサンプルを繰り越します。

## ESP32S3–CPU0プロトコル

既存のフレーム形式は、ヘッダ14 bytes、ペイロード最大96 bytes、
CRC-16/CCITT-FALSE 2 bytesです。フレーム分割・継続フラグはありません。

| type | 名称 | 方向 | ペイロード契約 |
|---:|---|---|---|
| `0x04` | `ACOUSTIC_FEATURE` | ESP32S3 → CPU0 | メタ8 bytes（event_id/frame_index/frame_count/n_bins/flags）＋int8 mel 32 bins×2 frames＝72 bytes |
| `0x05` | `PROTOTYPE_DATA` | 双方向 | 64次元int8埋め込み重心とメタ。1パケット96 bytes以内 |
| `0x10` | `SET_CONFIG` | CPU0 → ESP32S3 | 学習モード指令／プロトタイプ保存要求 |
| `0x11` | `ACK` | ESP32S3 → CPU0 | 保存結果／設定反映結果 |
| `0x22` | `POSE_TELEMETRY` | CPU0 → ESP32S3 | 姿勢・環境認識用データ |

`0x20`は既存の96-byteペイロードで満杯のため、新しい姿勢データには
`0x22`を使用します。`n_bins`、フレーム数、フレーム番号はメタデータに
含め、受信側がイベントの欠落と再組立状態を検査できるようにします。

## CPU0–CPU1状態語

状態語は、CPU1の累積値と単調増加ミリ秒をCPU0へ渡すための契約です。
現行実装の7語を10語へ拡張する際も、既存語の意味とcommit markerを変えません。

| 項目 | 固定契約 |
|---|---|
| 新規状態ID | `0x88`、`0x89`、`0x8A` |
| 既存状態ID | `0x81`〜`0x87` |
| 現行語数 | 7 |
| 拡張後の語数 | 10 |
| カウント | 左右の累積エンコーダ値を24-bitで送信し、CPU0で符号拡張付き剰余差分を計算 |
| 時刻 | CPU1の単調増加ミリ秒24-bit。commit時刻として使用 |
| commit marker | 既存の`SEQUENCE`語 |

デルタ値を直接送信しません。フレーム欠落や再送があっても、累積値と
commit時刻からCPU0側で変位と経過時間を再計算できるようにします。

## 実装状況の境界

この契約資料の存在は、各メッセージや10語拡張が実装済みであることを意味しません。
音響特徴量生成、`0x04`/`0x05`/`0x10`/`0x11`/`0x22`、状態語の7→10拡張は、
対応する実装とテストが揃った時点で個別に完了と判定します。現時点のTFLMランタイムは
固定int8モデルを実行する基盤であり、音響特徴量生成・現場学習・走行経路への接続は
別途実装が必要です。
