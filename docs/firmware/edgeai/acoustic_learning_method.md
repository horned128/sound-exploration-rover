# 音響の現場学習方式

最終更新: 2026-09-16 / 対象: Phase 2（音響識別AIと現場学習）/ 位置づけ: **方針と計画**

この文書は、現場学習の方式と識別方式を決めるための設計文書です。ESP32のイベント送信と
`task_infer`の起床機構は既に実装済みです。2026-09-16時点で、数式と境界条件を固定する
[ホスト参照実装](../../../software/acoustic-trainer/acoustic_learning.py)と9件の回帰試験を追加しました。
CPU0の背景AE・能動フレーム識別、`task_infer`への接続、32 KiB保存形式は実装済みです。
実録音でのしきい値測定とMRAM復元は、実機でのみ確認します。
[エッジAI設計](README.md)の固定契約（特徴量仕様・プロトコル・状態語）は変更しません。
決めるのは「再組立した特徴量をどう学習し、どう判定するか」だけです。

## 1. 結論

| 役割 | 方式 |
|---|---|
| **トリガ**（この環境で異常な音か） | **自己符号化器による背景モデルの常時学習**。再構成誤差が大きいイベントを候補とする |
| **識別**（それは学習させた音か） | **能動フレーム選別 ＋ 識別的距離**。再構成誤差は使わない |

この2つで完成形とします。オフラインで学習したモデルを一切必要としない構成です。

自己符号化器はトリガにだけ使います。**識別には使いません。** 理由は第3節にあります。

## 2. この方式を選ぶ理由

現場で扱う対象音は、会場の反射、床材、周囲雑音、音源までの距離で特徴が変わります。
対象／非対象を多環境で網羅したラベル付き録音をあらかじめ必要としないことを、音響機能の
設計条件とします。

背景モデルは非能動フレームだけでデコーダ重みを現場更新し、環境で普段見ない音を候補にします。
対象かどうかは、利用者が5回登録した個別見本との距離で決めます。候補生成と対象照合を分けるので、
再構成しやすい単純な非対象音を誤って対象とみなす問題を避けられます。

現場で重みそのものを更新するので、「音響特徴をエッジAIに直接学習させる」という
計画書の記述にも素直に一致します。

### 2.1 学習の形

自己符号化器のエンコーダを**乱数で固定**し、デコーダだけを**再帰的最小二乗法（RLS）**で
更新します。1サンプルごとに閉形式で解が進み、勾配も学習率もエポック数もありません。

入力 `x` に対し隠れ層 `h = φ(αx + b)`（`α`, `b` は固定）、再構成 `x̂ = W h`。
`W` と、隠れ層出力の相関逆行列 `P` を次で更新します。

```
k = P h / (λ + hᵀ P h)
W ← W + (x − W h) kᵀ
P ← (P − k hᵀ P) / λ
```

この形を選ぶ理由は3つあります。

- **エンコーダを保存しなくてよい。** 同じ乱数種から再生成できます。
- **発散しない。** 閉形式なので学習率の調整が不要で、マイコン上で安全に回せます。
- **推論フレームワークの学習機能が不要。** TFLMは推論専用なので、従来案では
  「学習」が重心の平均計算に留まっていました。この形なら重みが実際に更新されます。

計算量は隠れ層16・入力32で1サンプルあたり数千回の積和です。M85 1 GHz では誤差です。

## 3. 設計判断の根拠

方式を決める前に、ホスト上で使い捨ての実験を行いました。以下の数値はその結果です。
**実験コードは残していません。** 第6節のとおり、この判断を再現するホスト検証を
作るところから実装を始めます。

### 3.1 隠れ層を入力より広く取ってはいけない

学習対象の音のフレームで学習し、①学習外の同じ音、②一様乱数、
③各フレームのbinを並べ替えたもの（値の分布は同一、スペクトル形状だけ破壊）を採点しました。

| 隠れ層 | 学習対象 | 一様乱数 | bin並べ替え |
|---:|---:|---:|---:|
| 64 | 0.00000 | 0.00000 | 0.00000 |
| 32 | 0.00015 | 0.00942 | 0.00083 |
| 16 | 0.00416 | 0.09839 | 0.01565 |
| 8 | 0.00870 | 0.10569 | 0.01708 |

隠れ64（入力32より広い）は**一様乱数まで誤差ほぼ0で復元**します。
活性化関数が線形域にあると、デコーダはエンコーダの逆写像を学習して恒等写像へ崩壊し、
何を入れても「学習したもの」に見えます。

**入力32に対して隠れ16。真のボトルネックを置きます。**

### 3.2 再構成誤差は「復元しやすさ」であって「学習したものか」ではない

隠れ16で学習対象の音を学習し、各種の音を採点しました。

| 音 | 特徴量の分散 | 平均MSE |
|---|---:|---:|
| 学習対象（落下音） | 0.01169 | 0.00413 |
| 拍手 | 0.00330 | **0.00091** |
| ノック | 0.00996 | 0.00280 |
| 足音 | 0.00429 | **0.00149** |
| 声 | 0.02918 | 0.00755 |
| 定常トーン | 0.02770 | 0.01713 |
| 環境音 | 0.00585 | 0.00334 |

**入力の複雑さとMSEの相関は +0.84。** 単純な音ほど誤差が小さくなるので、
**拍手や足音が学習対象より「学習対象らしい」と判定されます。**

自己符号化器の再構成誤差は、入力の複雑さの尺度であって、学習分布への所属の尺度ではありません。
一クラス識別に使うと必ずこの偏りが出ます。

### 3.3 入力の作り方を変えても解決しない

マージンは「学習対象の受理率 − 最悪の非対象の受理率」です。正でなければ使えません。

| 変種 | マージン |
|---|---:|
| 再構成誤差・フレーム単位・隠れ16 | −10 pt |
| 再構成誤差・時間スタック k=4（隠れ32） | −2 pt |
| 再構成誤差・時間スタック k=8（隠れ64） | ±0 pt |
| 再構成誤差・時間スタック k=16（隠れ128） | −0 pt |
| 再構成誤差・フレームエネルギーを復元して追加 | −1 pt |
| 再構成誤差・能動フレーム選別 | −39 pt |
| 識別的距離（cosine）・全フレーム | ±0 pt |
| **識別的距離（cosine）・能動フレーム選別** | **+42 pt** |

時間方向の文脈を足しても、契約が捨てたフレームエネルギーを復元しても効きません。
原因は時間情報の欠落ではなく3.2の偏りです。
**再構成誤差を判定に使う限り、入力をどう作り直しても解決しません。**

> ★**+42 pt の内訳に注意。** この実験では拍手の能動フレームが0個になり、
> 要約ベクトルが零ベクトルになって距離1.0で棄却されました。
> **識別できた証拠ではなく、イベントごと消えた結果です。**
> 実環境では短く広帯域な「対象音」も同じように消え得ます。
> 4.2節の「判定不能」はこの観測から導いた必須要件です。

### 3.4 背景モデルとしてなら確実に効く

環境音だけで背景モデルを常時学習し、再構成誤差が大きいものを「異常」とします。

| 音 | 異常と判定された割合 |
|---|---:|
| 環境音 | **1 %** |
| 落下音 | 100 % |
| 拍手 | 100 % |
| ノック | 100 % |
| 足音 | 98 % |
| 声 | 96 % |
| 定常トーン | 100 % |

**「この環境にとって異常な音が鳴った」の判定は確実に動きます。**
自己符号化器を採用するのはこの範囲です。

### 3.5 この数値の扱い

実験に使ったのは解析的に生成した合成音です。XVF3800のAEC・AGC・ノイズ抑制、
室内残響、ローバー自身の駆動音、マイク特性を一切模擬していません。

- **否定的な結論は採用します。** きれいな合成信号で分離できない方式が、
  残響とAGCのかかった実音声で良くなることはありません。3.1〜3.3は設計判断として確定します。
- **肯定的な数値は採用しません。** 3.3の+42 ptと3.4の分離率を
  **識別精度として引用してはいけません。** しきい値は実録音で決め直します。

## 4. 採用する構成

```
イベント検出                     識別
─────────────                    ────────────
背景モデルを常時学習              学習モードで対象音を登録
（能動フレームが無い間だけ）       （5回・能動フレームのみ）
      ↓                               ↓
再構成誤差 > θ_bg                 能動フレーム選別
＝この環境で異常                        ↓
      ↓                           識別的距離 < θ_id
      └───────────────────────────▶  ＝学習させた音 → 走行開始
```

### 4.1 トリガ — 背景モデル

| 項目 | 値 |
|---|---|
| 構造 | 32入力 → 隠れ16 → 32出力。エンコーダは乱数固定、デコーダはRLSで更新 |
| 入力正規化 | int8のlog-melを ±64 LSB でクリップし `[0, 1]` へ写す |
| 活性化 | Hard Sigmoid `clip(0.2x + 0.5, 0, 1)` |
| 忘却係数 | `λ = 0.95`（実効窓 約20サンプル） |
| 初期化 | `P = I / 0.01` |
| しきい値 | 学習済みフレームの `平均 + 3σ` |
| ★学習ゲート | **能動フレームが検出されていない間だけ学習する** |

ホスト参照実装はseed `0x53455231`の32-bit LCGでエンコーダ重みを生成し、重みを`[-1,1]`、
biasを`[-0.5,0.5]`から作る。CPU0実装も同じ系列を使用する。これはエンコーダを保存せず
再生成できることを、実装レベルでも固定するための仕様である。

**入力正規化は必須です。** Hard Sigmoidの出力域は `[0, 1]` なので、
これを超える入力は原理的に再構成できず、MSEが上限に張り付いたまま動かなくなります。
log-melのint8は概ね ±16 の対数値をスケールした値なので、必ず写像を挟みます。

**学習ゲートは安全上の要です。** ゲートを外すと背景モデルが対象音そのものを吸収し、
異常判定が永久に発火しなくなります。

### 4.2 識別 — 能動フレーム選別と識別的距離

フレーム毎のレベル正規化（固定契約）により、無音フレームは全ビンが同じ値になり、
int8では全ゼロベクトルになります。つまり**フレームの標準偏差そのものが活動量の代理**です。
契約がフレームエネルギーを捨てていても、能動フレームを選別できます。

| 項目 | 値 |
|---|---|
| 能動フレームの条件 | int8フレームの標準偏差 > **12 LSB**（実測で調整する初期値） |
| 実験時の能動フレーム数 | 落下音29 / ノック28 / 声36 / 足音6 / 環境音1（80フレーム中） |
| 要約 | 能動フレームの `{mean, std, max}` × 32 bin = **96次元** |
| 距離 | 登録した個々の見本への cosine 距離の最小値。**重心は使わない** |
| しきい値 | 見本のleave-one-out距離の `平均 + 3σ` |
| ★能動フレーム不足 | 初期 `N_min=10`未満なら**「判定不能」**を返す。「対象音ではない」と返してはならない |

重心ではなく個々の見本を残すのは、5回の発音のばらつきを平均で潰さないためです。

96次元の並びは`mean[32]`,`std[32]`,`max[32]`とする。mean/stdは最も近いint8へ半端を
ゼロから遠ざけて丸め、stdは`[0,127]`に飽和する。stdは32binの母標準偏差（`ddof=0`）を
使い、能動条件は**厳密に**`std > 12`とする。これらはCPU0と
[ホスト回帰](../../../software/acoustic-trainer/tests/test_acoustic_learning.py)の共通契約である。

**能動フレームが0個のイベントを距離1.0として扱ってはいけません。**
3.3の注記のとおり、実験では拍手が能動フレーム0個になり零ベクトルとの距離1.0で棄却されました。
机上では正しく見えますが、実環境で短く広帯域な**対象音**が同じ条件に落ちると、
同じ経路で取り逃がします。判定不能は走行を開始しませんが、
**誤検知でも正検知でもなく、診断へ記録して `N_min` としきい値の調整材料にします。**

### 4.3 純関数として実装する

既存の `sound_follow_controller_step()` と同じ規律に従います。
入力構造体から出力構造体へ、I/Oもグローバルも持ちません。
`software/control-sim/` のオフターゲット試験でそのまま回帰できます。

想定するファイルは次の2つです。どちらも `CPU0/src/services/`（L2）に置きます。

| ファイル | 責務 |
|---|---|
| `background_model.c/.h` | 乱数固定エンコーダ ＋ RLSデコーダ。学習・採点・状態の直列化 |
| `acoustic_identifier.c/.h`（既存を改修） | 能動フレーム選別 ＋ 96次元要約 ＋ 見本へのcosine最小距離 |

## 5. 固定契約への影響

| 契約 | 影響 |
|---|---|
| 音響特徴量（16 kHz / 400点窓 / 512点FFT / 160点ホップ / 32 bin / int8 / フレーム毎レベル正規化） | **変更なし**。能動フレーム選別は受信側の処理で、線上のデータは同じ |
| `0x04 ACOUSTIC_FEATURE` | **変更なし** |
| `0x05 PROTOTYPE_DATA` | **不使用**。学習も保存もCPU0内で完結するので線上へ出す必要がない。型番は予約したまま実装しない |
| `0x10` / `0x11` / `0x22` | 変更なし |
| CPU0–CPU1状態語 | 変更なし |

### 5.1 MRAM予約領域の拡大

保存対象と容量は次のとおりです。予約領域を**4 KiBから32 KiBへ拡大**します
（`0x0207F000` → `0x02078000` 始まり）。

| 対象 | 容量 |
|---|---|
| 背景モデルのデコーダ `W`（32×16 float32） | 2 KiB |
| 見本 5件（96次元 int8） | 480 B |
| しきい値・世代・CRC-32・乱数種 | 数十B |
| 予備（見本数の増加、隠れ層の拡大、A/Bスロット2面分） | 残り |

**相関逆行列 `P` は保存しません。** 採点に不要で、継続学習を再開する場合だけ
初期値から作り直します。**エンコーダは乱数種から再生成するので保存しません。**

★**予約領域の先頭が動くため、旧レイアウトで保存済みの実機は別の場所を読みます。**
世代番号とCRC-32で弾けるはずですが、その経路を実機で確認してください。
偶然CRCが通る古いスロットを読むのが最悪の事例です。

## 6. 実装の順序

1. **ESP32S3のイベントトリガと `0x04` バースト送信。**
   方式に依存しない最上流で、これが無い限り下流は一切検証できません。
2. `task_infer`（優先度11・イベントフラグ起床）。方式に依存しません。
3. **第3節の判断を再現するホスト検証を作る。** **完了（2026-09-16）**。
   `software/acoustic-trainer/acoustic_learning.py` と9件の回帰で、固定エンコーダ、RLS、
   学習ゲート、能動選別、96次元要約、cosine、leave-one-out、判定不能を固定した。
   合成データの肯定的な精度値は再現・引用しない。
4. 能動フレーム選別と識別的距離の純関数。**完了（2026-09-16）**。
   CPU0 `acoustic_identifier.c/.h`へ実装し、control-simの該当10件で回帰した。
5. 背景モデルの純関数と学習ゲート。**完了（2026-09-16）**。
   CPU0 `background_model.c/.h`へ実装し、上記を含むcontrol-sim該当17件で回帰した。
6. MRAM予約領域の拡大と保存形式の更新。**完了（2026-09-16）**。
   `prototype_storage.c`で32 KiBを16 KiB×2スロットとして扱い、背景デコーダ、5件の
   96次元見本、しきい値、CRC-32、世代を保存する。CPU0 Generate + Clean Buildは0 errors。
7. 実録音の収集と、しきい値・分離性能の再測定。**未実施（実機作業）**。

## 7. 実機で確認すること

1. 学習モードで5回発音し、能動フレームが各回で10フレーム以上取れること。
   取れない場合は `12 LSB` を実測で調整する。
2. 電源を切って再投入し、見本と背景モデルが復元されること。
   旧レイアウトのデータが残っている個体で、世代番号とCRC-32が正しく弾くこと。
3. 距離と音量を変えて同じ音源が同じ判定になること（レベル正規化の検証）。
4. **学習ゲートの確認。** 学習モードでない状態で対象音を鳴らし続けても、
   背景モデルがそれを吸収して異常判定が鈍らないこと。
5. 対象音以外（拍手・足音・ドアの開閉）での**誤発進回数**を記録すること。
6. **判定不能の発生率**を記録すること。対象音で頻発するなら `N_min` か `12 LSB` が高すぎる。

## 8. 計画書との整合

計画書は「その音響特徴をエッジAIに直接学習させる」と記載しています。

- **背景モデルはこの記述に正面から一致します。** 重みを現場で更新する教師なし学習であり、
  オフライン学習済みモデルを必要としません。
  床材や環境ノイズへの適応という計画書のアピールポイントをそのまま実演できます。
- **識別側はニューラルネットではありません。** 能動フレーム選別とcosine距離です。
  **識別を「学習済みNNによるエッジ推論」と呼びません。** 発表時はこの区別を明示します。
- TFLMは Phase 4-1b の障害物回避MLP（視覚/空間AI）で使います。
  Phase 1 のベンダリングと計画書の記述は、そちらで成立させます。
