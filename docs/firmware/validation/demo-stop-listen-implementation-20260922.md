# 音源追従・停止聴取シーケンス実装（2026-09-22）

実機走行検証を経て確立された音源追従・停止聴取シーケンスを、CPU0の既定動作へ反映した。
目的は不完全な推定距離による早すぎる自律到着誤認を防ぎ、学習済み音への選択反応、障害物回避、回避後の停止・再聴取、再接近、音停止による終了待機・安全停止を一連で安定動作させることである。

## 実装した制約

1. 学習済み見本が存在する場合は、既存の識別一致を満たす音だけがDoA取得・走行へ進む。
2. `CPU0_SOUND_STOP_AND_LISTEN_ENABLE=0` では、停止中に安定した5個のDoAで走行を始め、対象音が続く間は走行中にも安定DoAで方向を更新する。位置推定bearingは操舵に使わない。
3. `CPU0_SOUND_USE_LOCALIZATION_FOR_STEERING=0` と `CPU0_SOUND_USE_LOCALIZATION_FOR_ARRIVAL=0` により、現状のbearing-only位置推定は診断テレメトリ専用とし、直接の操舵・終了理由には使わない。
4. ToF回避を音源追従中にだけ開始し、開始した回避側は安全な前方・左右クリアランスまで保持する。クリアランスを確認した周期に`avoidance_completed`を通知する。
5. `avoidance_completed`を受けたCPU0は、同一周期で停止、DoA履歴破棄、500 ms整定へ遷移する。その後、連続音でも新しいDoAを5個取り直す。回避後のDoAが35度を超える場合は、空き側へ向けた回避ピボットとは別に、音源の左右符号どおりのX字旋回を済ませてから再接近する。
6. 対象音が1.5秒途切れると、`SETTLE → COOLDOWN → LISTEN`へ入り、左右RPMは0のまま停止する。再び走行するには、対象音を再検出する必要がある。
7. `CPU0_USE_CONTROL_MLP=1`および`CPU0_SOUND_ALLOW_CONTROL_MLP=1`により、既定の通常走行はMLPの操舵・速度計画を使う。MLPへ渡す`target_bearing_deg`は走行中の安定DoAで更新される。

## 観測する状態遷移

対象音が続く通常経路は`LISTEN → STEER_PREP → MOVE_STEP`であり、`MOVE_STEP`中もDoAとMLP出力を更新し続ける。対象音を1.5秒失うと`SETTLE → COOLDOWN → LISTEN`へ移り停止する。`LISTEN`、`SETTLE`、`COOLDOWN`、到着停止ではCPU1へアクチュエータ無効指令を送り、サーボPWMとモーターを停止する。`STEER_PREP`と`SPIN_PREP`だけは次の動作へ必要な操舵整定を行う。
電源投入直後だけは例外として、CPU1が駆動モーターを停止したまま全操舵を0度へ1000 ms整定し、PWMを停止する。前回の電源断時に残った舵角を次の`LISTEN`中まで保持しないための一回限りの初期化である。
障害物では `SENSOR_PIVOT_*` または方向保持付き通常操舵を経由し、クリア後に必ず `SETTLE → LISTEN` へ戻る。再取得DoAが±35度を超える場合は、さらに `SPIN_PREP → SPIN_STEP → SETTLE → LISTEN` を経由する。終了・待機時は `WAIT_RESTART`（停止聴取モード時）または `LISTEN` 停止であり、`ARRIVED`は使用しない。

## 実機前の確認順

1. `LISTEN`中に、未登録音では`STEER_PREP`へ進まず、登録音だけで進むことを確認する。
2. 障害物なしで、対象音が鳴っている間は`MOVE_STEP`を維持し、音源を動かしたときに`think.steering_deg`が追従することを確認する。
3. 障害物1個で、回避中に回避側を保ち、通過後に`SETTLE`が出ることを確認する。再取得したDoAが大きければ、`SPIN_STEP`の左右RPMがDoAの符号に対応してから前進することを確認する。
4. 音を止め、約1.5秒後に`SETTLE`、続いて`COOLDOWN`または`LISTEN`で停止を保つことを確認する。

この実装は、実機の音源位置推定精度や自律到着判定を保証しない。到着距離の緩和は現行実装には含めない。
