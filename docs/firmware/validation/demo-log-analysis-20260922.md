# DEMO実機ログ解析と追従調整（2026-09-22）

対象ログ: `software/rover-monitor/logs/rover-monitor-20260922-092440.jsonl`

## 実測した課題

- DoA 1,653サンプルはすべてXVF3800のフォールバック値だった。
- 学習済み音の一致は249サンプルあり、そのうち160サンプルは `vad=0`、さらに109サンプルは開始音量を満たしていた。
  従来の「VADが1でなければ有効音でない」という条件では、鳴り続ける学習済み音を静音と誤認する余地があった。
- 09:24:50の追従開始では `doa_deg=326`（生値293）に対し、旧設定は `steering_deg=-45` で左操舵を出した。
  このログには音源の実位置が記録されていないため、符号だけを最終確定する証拠にはならない。現設定は実機観察に合わせた反転のまま保持し、固定音源による左右校正で確定する。
- 09:29:19にはDoA約178°でスピンターンへ入った。これは誤った左右操舵の積み重ねで音源を後方扱いした結果とも整合するため、まず方位符号を是正し、低品質なDoAは走行に採用しない。
- 旧ToF反発は左右850 mm、正面950 mmから働いた。実ログの800〜900 mm台でも音源操舵へ大きく加算されるため、開けた場所で不要な旋回を生む要因になった。

## 実装した調整

| 項目 | 旧 | 新 |
|---|---:|---:|
| XVF DoAの左右符号 | 時計回りを右正 | 時計回りを左正として反転 |
| 走行DoAの最小品質 | なし | 40 / 100 |
| 生DoAと平滑DoAの整合 | 未確認 | 差が20°超の観測を走行から除外 |
| 学習済み連続音の有効判定 | DoA・音量・VAD・一致 | DoA品質・音量・一致（VAD非依存） |
| ToF反発の開始距離 | 側方850 mm / 正面950 mm | 側方・正面とも700 mm |

通常のDEMO経路では `COOLDOWN` を待たない。学習済み音が音量閾値以上で継続する限り、
`LISTEN → STEER_PREP → MOVE_STEP（最大1秒）→ SETTLE（500 ms）→ LISTEN` を繰り返す。
1.5秒以上、解除音量未満になったときだけ終了停止へ移る。

## 次回の実機確認

1. 障害物のない場所で、音源を右前方に固定して学習済み音を連続再生する。
   `think.steering_deg` が正、左RPMが右RPM以上となり、右へ進路を取ることを確認する。
2. 同じ距離で音源を左前方へ移し、上記の符号が反転することを確認する。
3. 0.8 m以上の空間では音源由来の操舵を維持し、700 mm未満へ障害物が入った場合だけ回避が重畳することを確認する。
4. ログでは `audio.raw_doa_deg`、`audio.doa_deg`、`audio.confidence`、`think.steering_deg`、`command.left_rpm/right_rpm` を同じ時刻で確認する。

上記の左右テストでまだ逆向きになる場合は、`CPU0_SOUND_DOA_ZERO_OFFSET_DEG` を実機の正面角に合わせて校正する。180°ずれている場合はこの値を180へ変更し、左右の反転自体は戻さない。

## 追加ログの再調査（10:25:18〜）

`rover-monitor-20260922-102518.jsonl` では、DoA品質下限を40へ下げた後に
`LISTEN → STEER_PREP → MOVE_STEP` が実際に進行しており、「LISTENから動かない」問題は解消した。

- TARGET・音量・品質40以上の観測342件のうち、26件（7.6%）で `raw_doa_deg` と `doa_deg` の円周差が20°を超えた。最大差は148°だった。
- たとえば `raw=74° / doa=74° / steering=-45°` のように、走行時の最終 `think.steering_deg` はToF回避と合成された値である。これだけでは音源方位の符号誤りか、障害物回避の上書きかを区別できない。
- 新ファームではこの不整合フレームをDoA取得から外し、`navigation.bearing_deg` に「静止中に確定したDoA」を記録する。次のログでは `navigation.bearing_deg`（音源へ進むべき向き）と `think.steering_deg`（障害物回避後の向き）を比較できる。

次回は障害物のない場所で左右前方の固定位置を各10回ずつ測定し、`navigation.bearing_deg` の符号と実際の車体進行を対応付ける。そこで一貫して逆なら `CPU0_SOUND_DOA_CLOCKWISE_POSITIVE` または `CPU0_SOUND_DOA_ZERO_OFFSET_DEG` を校正する。一部だけ逆なら、DoA入力品質または回避合成が原因である。

## 11:14〜11:22の5走行後の回避復帰（2/5成功）

利用ログ: `rover-monitor-20260922-110708.jsonl`、`rover-monitor-20260922-111424.jsonl`。

実機観察の失敗3件は、音源方位の再取得より前に、回避コントローラ自身が壁際で
不適切な状態へ入ることが主因だった。

- 11:17:29の例では、`SENSOR_PIVOT_RIGHT`直前にToFが左/中央/右 =
  `64 / 224 / 1253 mm`、直後に `44 / 119 / 328 mm` となり、旧処理は
  正面近接を3観測確認した時点で `SENSOR_BLOCKED_STOP` へ永久ラッチした。
  その後に音を鳴らし続けても、新しい音源方位では脱出できない。
- 旧ピボットのヨー進行不足／時間超過は、現在のToFや音源方位を見ずに
  `direction = -direction` で反転していた。そのため壁へ面した後に、空き側・
  音源側と反対へ再旋回し得た。ユーザー観察の「左へ立て直すべき所で右へ回る」
  に一致する。
- 強い回避操舵28°は、クリアランス条件がそろうまで維持された。横壁を見続ける
  通路では解除されず、回避が通過後も過大化した。さらに、旧`COMMIT_MAX_MS`の
  計時はヨー目標を越えると止まるため、この状態を上限時間で抜けられなかった。

### 今回の修正

| 問題 | 修正 | 実機上の期待動作 |
|---|---|---|
| 正面で停止固定 | `150 mm`以下を2連続確認すると、まず `SENSOR_BACKUP` で85 RPM・700 ms後退 | 2回目のような正面停止から距離を取る |
| ピボット不成立時の無限反転 | 後退後に最新ToFの空き側を優先し、左右差が小さければ静止中に確定した音源方位側を選び直す。後退・再旋回は最大2回 | 壁へ向かう機械的な左右反転をしない。なお脱出不能時だけ安全停止へ収束する |
| 回避し過ぎ | 先行回避を `850 mm / 250 mm差` から `800 mm / 350 mm差` へ絞る。強い28°操舵は30°回頭まで、または前方500 mm未満だけとし、その後は同方向12°へ緩和 | 小さな左右測距差で壁側へ大きく曲がらず、回避方向そのものは反転しない |
| 回避後に曲がり続ける | 実時間で回避セッションを計時し、前方700 mm以上で2.5秒に達すれば停止・再聴取へ戻す | 音源への向き直しを新しいDoAで行う |

`BACKUP`中は前方ToFが同じ壁を見続けても衝突カウンタへ加算しない。後退を終えた
時点のToFと、今回の移動前に静止中で確定した`target_bearing_deg`だけを使って
ピボット方向を決める。
