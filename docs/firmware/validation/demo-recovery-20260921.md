# 2026-09-21 DEMOログ診断と短期実演案

## 結論

優先するのは、誤った音源位置に走行を引っ張られないこと、回避後に停止して音源方向を再取得すること、終了時の停止を保持することである。到着距離や品質閾値だけの緩和は勧めない。既に開始直後を「音源まで数cm」と誤推定する記録があり、途中で誤到着する危険がある。

短期の推奨実演は「学習した音だけに反応 → 障害物を回避 → 停止して再聴取 → 音源へ接近 → 音の停止で終了停止」。最後は**音停止による終了**と説明する。自律的な音源到着判定が完成したと説明しない。この実演にも下記の制御修正と実機確認が必要であり、現状のままの成功を保証するものではない。

今回は調査・提案のみ。既存の作業中ファームウェア、設定、マップは変更していない。

## 対象・分析限界

- `test_map.drawio`: 中央に半径11cmの障害物、roverとの間に90cm、roverと口笛位置の間に220cmの寸法表記。図の描画座標から部屋の寸法や実物の車幅を逆算しない。
- `software/rover-monitor/logs/rover-monitor-latest.jsonl` の実体は `rover-monitor-20260921-231546.jsonl`。892行、23:15:46.955〜23:20:47.764 JST。
- 再起動は `esp_ms` の大幅な逆行で区切り、`usb.cpu_ms` と `pose.uptime_ms` の同時リセットで照合。境界は316、330、340、358、513、602、770行目。
- `audio.age_ms`、`sensors.age_ms`、`cpu_age_ms` 等は更新データの鮮度で、通常更新でも戻る。起動区切りには使わない。
- ログには実測の車体位置、発音時刻、発音位置、モーター音のみの区間、実機のビルド識別子がない。認識の正解率、反射音の寄与、実機への最新ソース反映は断定できない。
- テレメトリ各節には取得時刻差がある。サンプル数を制御内部の観測回数や時間割合と混同しない。

## 確認できた問題

### 1. Source bearingは直接測った口笛方向ではない

`sound_source_localizer.c` が、DoAとオドメトリから世界座標の音源位置を推定し、そこへの相対角を生成している。monitorの青矢印はこの推定値で、音響DoAの矢印とは異なる。

- 起動1、145行目、23:16:24.501: 車体 `(160,-25)mm`、推定音源 `(158,-4)mm`、距離21mm、bearing -111°、品質58。
- 起動6、539行目: 約165mm進んだ位置で音源距離43mm。
- 起動7、625行目: 約151mm進んだ位置で音源距離55mm、bearing -177°。
- 起動8、797行目: 約202mm進んだ位置で音源距離190mm、bearing +163°。

ユーザー提示の固定音源配置と整合しない近傍推定が、開始直後から出ている。走行・旋回中も観測を取り込むため、マイク方位の変動、平滑化遅延、車体姿勢との時間差、車輪滑りなどが交差角に混入する可能性がある。残差が小さくても真の音源位置とは限らない。

### 2. 古い誤推定が新しい音で有効化され続ける

`sound_source_observation_push()` は採用可能な音を受けるたびに `last_sound_ms` を更新する。一方、`navigation_target_valid` は最後に**位置推定が成功した時刻**をチェックせず、その音の時刻を使う。`source_valid` 自体も失効時に消されない。

このため、推定の幾何条件を満たさない音でも古い位置の有効期限を延ばせる。一度期限切れになった音源位置も、新しい音だけで復活し得る。

ログでは `target_valid=1` が480行。そのうち401行は `geometry_valid=0`。短い保持自体は妥当だが、無期限の再延長を許す仕組みが問題。

### 3. 到着条件とfallback品質上限が合わない

`acoustic_frontend.c` はfallback時のDoA品質を最大70に制限する。位置品質はその値に1以下の係数を掛けるので最大70。

`control_config.h` の到着条件は距離450mm以内、品質65以上、正面±25°以内。正面以外は品質80以上が必要なため、今回の経路ではこの救済条件を満たせない。さらに今回の幾何成立・有効音・繰返し確認が必要。

ログ上、目標有効かつ距離450mm以内は91行、そのうち品質65以上は23行、さらに正面±25°以内は0行。実際の到着候補も全行0。

単に65を下げる、450mmを広げるだけでは、上記の開始直後の誤推定を誤到着として採用してしまう。

### 4. 回避後の再聴取と回避方向保持が不足

- 障害物回避は原則45°回頭で終了し、終了時のクリアランス待ちはない。
- 通常操舵の方向保持閾値は25°。45°回頭を終えた直後には、その角度条件による最低操舵保持は既に対象外。
- MLP採用時の最終操舵は `mlp_output.steering_deg`。ルール側で算出した通常時の方向保持操舵を、そのまま最終出力へ保証する構造ではない。
- 回避中も音源追従の内部状態機械が進み、回避終了専用の停止・静定・DoA履歴破棄・再取得がない。
- 現在のMOVE_STEPは連続追従で、`CPU0_SOUND_MOVE_STEP_MS` を満了して必ず停止する経路ではない。設定値を短くするだけでは停止聴取型に戻らない。
- MLPは `target_heading_deg` を想定するが、呼び出し側は最大±45°に制限された `sf_output.steering_deg` を渡す。後方音源と前側の大操舵要求を区別できない。

したがって45°を別の固定角へ変えるだけでは、障害物を通過するまでの経路保持と正しい音源方向への復帰を解決しない。

### 5. 到着状態が終了ラッチになっていない

`sound_source_localizer_step()` は音の有効期限が切れるとARRIVEDからもSEARCHへ戻す。`sound_follow_controller_step()` は到着入力がなくなるとLISTENへ戻る。到着後に音を止め、別の音で再発進する余地がある。終了をリセット操作まで保持する状態が必要。

### 6. 口笛の識別と、口笛方向の測定は別の経路

学習見本と音の特徴が一致しても、XVF3800が返す方位がその口笛を指している保証はない。起動8では最初の発進前にraw DoAが90°を保持し、起動1の発進前はほぼ0°だった。同じ位置・姿勢という前提なら入力方向から不安定であり、Source bearing表示だけの問題ではない。

XMOSの公式説明では、processed DoAはspeech energyに基づきビーム方向を選ぶ。人の口笛、室内反射、自己雑音、保持された方向のどれが支配的かは今回のログだけでは分離できない。口笛を録音再生しても方向推定が必ず改善するわけではない。

Seeed公式DoA例はXVFファームウェアによりcommand IDが異なり、v1.0.7では19、掲載コードは18。ローカル実装は18固定。搭載版の確認は有用だが、892行のfallbackだけからバージョン不一致と断定して書き換えない。

## 短期修正の優先順位

| 優先 | 修正内容 | 確認する効果 |
|---|---|---|
| P0 | DEMO用に推定位置からの操舵を切り離し、停止中に確認したDoAを基準に短い移動を行う。生DoAをそのまま連続追従する変更にはしない | 自車付近の偽音源・古い位置による逆操舵を防ぐ |
| P0 | 回避終了後に実測停止→静定→履歴破棄→DoA再取得を必須化。再取得できなければ停止 | 回避中の自己雑音と旋回前の方向を持ち越さない |
| P0 | 音を見失った後の走行時間に実時間で上限を設ける。DEMO終了停止は明示的な再開まで保持 | 口笛の切れ目・終了時に進み続けない |
| P1 | 回避側を決め、車体が障害物を通過する区間ではその側を維持。MLP出力にも同じ制約を適用 | 一回曲がった直後に障害物側へ戻る動作を抑える |
| P1 | MLPには本来の目標方位を渡す。後方音源は前進大操舵で追い続けず、停止して再方向合わせ | 回避後の進行方向を整える |
| 継続開発 | 位置推定成功時刻の独立管理、DoAとの整合性検査、観測位置の間引き、時間同期、オドメトリ校正、到着ラッチ | 本来の自律到着を安定化 |

停止聴取を導入するだけで現在の距離推定も良くなるとは限らない。12観測のFIFOに同じ停止位置の観測を連続投入すると、別位置の観測が押し出され基線が消える。位置推定を残すなら、異なる停止位置の代表観測を保持する設計が必要。

## 実演の組み方

### 推奨: 呼び出し・回避・再接近

1. まず別の音には反応せず、登録した音でのみ動き出すことを見せる。
2. 障害物1個のコースを進み、回避する。
3. 回避後の停止・再聴取を見せ、同じ音源へ再び向かう。
4. 接近後に音を止めて終了停止。説明は「音停止で終了」。これは位置推定による自律到着とは区別する。

配置変更可能なら、音源を中心線から片側へ30〜50cmずらすことを試験開始値とする。左右対称を崩し、通る側を作る意図であり、保証寸法ではない。障害物の半径だけでなく車体幅・旋回時の掃引に対する通過余裕を取る。障害物が走行に影響しない位置まで移して「回避できた」と評価しない。

録音再生可能なら、発音の揺れと高さの条件を固定できる。スピーカーをマイクに近い高さへ置き、使う再生音そのものを登録する。最初は同じ口笛で比較し、静止時の方位が不安定なら、短い音声なども候補として実測する。音を変える場合は目的音としての識別も確認し直す。

床のテープを置くだけでは現センサー構成で終点を検出できない。また「対象音が聞こえ、正面ToFが近い」だけでは、中間障害物と終点を区別できない。この簡略条件を自律到着として採用しない。

### 予備: 2つの機能を連続して見せる

「登録音の選択反応と向き合わせ」「障害物への減速・回避」を短い別場面として実演する。長い完走や距離推定を必須にせず、認識結果・ToF・操舵・制御採用状態を一緒に提示する。通常領域の制御MLPと、近接時のルールによる回頭を分けて説明する。

現ログにMLP採用・fallbackの明示フラグはないため、ログだけで『全てMLPで回避した』と説明できない。現音響コードは背景モデル更新と特徴要約の見本照合が中心で、現行経路の説明に古いCNN資料をそのまま使わない。

## 試行錯誤を増やさない確認順

1. **静止方位を先に確認**: 最終取付姿勢、モーター停止で、前・右・左から同じ音を各3回。まずraw/filtered DoAを見る。実演向けの暫定合格基準は3回とも正しい側、前方は±20°程度以内。ここで大きく飛ぶなら走行パラメータの調整へ進まない。
2. **障害物なし**: 同じ開始位置から1m程度の接近と音停止を3回。短い無音を挟む条件も含め、定めた猶予で停止し、終了後は勝手に再開しないことを見る。
3. **障害物1個**: 提示コースで回避側保持・回避後の再聴取・再接近を3回。接触なし、往復旋回なし、終了停止の3条件で判定。3連続成功はリハーサルの目安であり、統計的な成功率保証ではない。
4. 静止方位が安定しない、または同じ原因で完走を繰り返し失敗するなら、予備の分割実演へ切り替える。到着閾値を無作為に変え続けない。

各試験では起動番号・発音時刻・実際の音源方向を簡単に記録し、可能なら映像とログを合わせる。これにより反射・識別・操舵の原因を分けられる。

## ホスト上での検証

既存の `software/control-sim/.venv/bin/python -m pytest -q tests/test_sound_source_localizer.py` は **5 passed**。これは現行の理想方位入力のテストが通るという意味で、実環境の安定性保証ではない。到着確認テストは品質90を使っており、今回のfallback上限70とは条件が異なる。

実際のC推定器を既存ctypes bindingで動かし、次も確認した。

- 品質70で2地点から `(981,0)mm` の音源を推定し、音を止めて観測を失効させるとtargetは無効になる。その後同じ地点から異なる方向の音を20秒以上入力すると、基線0・geometry無効のまま古い `(981,0)mm` がtarget有効に戻った。新しいDoAは-90°なのにsource bearingは+17°のまま。
- 品質90の理想観測でARRIVEDを成立させた後、音を止めて4秒時点で更新するとSEARCHに戻った。

実機書き込み、実走、音響測定、ファームウェア修正は実施していない。
