# 第2章: 音の基礎とDSP入門（サンプリング・窓関数・フーリエ変換）

本章では、マイクが拾った空気の振動がどのようにしてコンピュータで扱えるデジタルデータになり、なぜそれを「周波数成分」に変換しなければAIが理解できないのかを、数式アレルギーの方でも直感的に理解できるように解説します。

---

## 2.1 音とは何か？ 空気の波を数値にする

### 音の正体は「空気の圧力の揺れ」
音とは、物体が振動したときに周囲の空気が押されたり引っ張られたりして生じる **「空気の圧力振動（粗密波）」** です。
- **振幅（波の高さ）**: 圧力がどれだけ大きく変化したか $\rightarrow$ **音の大きさ（音量）**
- **周波数（1秒間に波が何往復するか、単位: Hz）**: 波の細かさ $\rightarrow$ **音の高さ（ピッチ）**
  - 例: 人の話し声（100 Hz 〜 3,000 Hz）、救助笛（約 2,000 Hz 〜 4,000 Hz）、モータのうなり音（数百 Hz）

```text
空気の波:  〜〜〜〜〜（粗密波）
             ↓
マイク:    [ダイヤフラム (薄膜) が振動]
             ↓
電圧信号:  〜〜〜〜〜（連続的なアナログ電圧）
             ↓
ADC:      [1秒間に何万回も電圧を測って数値にする（標本化 & 量子化）]
             ↓
デジタルデータ:  [+120, +540, +1200, +850, -320, -1100, ...] (PCMデータ)
```

---

## 2.2 サンプリング定理: なぜ「16,000 Hz」なのか？

### サンプリング周波数（$F_s$）とは？
マイクの電圧を「1秒間に何回デジタル値として記録するか」を表す数値です。
SEROVでは、音響DSP（XVF3800）から **$16,000\text{ Hz}$（16 kHz）** で音声を取り込んでいます。
つまり、**「1秒間に16,000回（約62.5マイクロ秒に1回）」** 音の大きさを記録しています。

### なぜ16 kHzで十分なのか？（ナイキスト＝シャノンのサンプリング定理）
「音楽CDは44.1 kHzなのに、16 kHzで足りるの？」と思うかもしれません。
ここで登場するのが、デジタル信号処理で最も有名な **サンプリング定理** です。

> [!NOTE]
> **サンプリング定理（Nyquist-Shannon Sampling Theorem）**
> サンプリング周波数を $F_s$ とするとき、記録・復元できる音の最高周波数は **$\frac{F_s}{2}$（ナイキスト周波数）** までである。

- サンプリング周波数が $16,000\text{ Hz}$ の場合、復元できる音の上限は **$8,000\text{ Hz}$（8 kHz）** です。
- 人間の声（会話）の主要なエネルギーは $300\text{ Hz} \sim 3,500\text{ Hz}$ に収まります。
- レスキュー用の救助笛や警報音も $2\text{ kHz} \sim 4\text{ kHz}$ です。
- つまり、探査ローバーにとって **8 kHz以上の超高音（コウモリの鳴き声やハイレゾ音楽の倍音など）は全く不要** であり、データ量を節約してマイコンを高速に動かすためには **16 kHzが最も合理的かつ黄金比の選択** なのです。

### 32-bit PCM とは？
XVF3800からI2S経由で送られてくるデータは「32-bit signed PCM」です。
これは、音の振幅を $-2,147,483,648 \sim +2,147,483,647$ の32ビット符号付き整数で表したものです。
`audio_capture.c` では、この値を `INT32_MAX` で割ることで、数学的に扱いやすい $-1.0 \sim +1.0$ の範囲に正規化しています。

## 2.3 なぜ生の波形のままではAIが理解できないのか？

「マイクから波形の数値データが得られたなら、それをそのままニューラルネットワークに入れればいいじゃないか」と思いますよね。
実は、**波形（時間領域データ）をそのままAIに食わせると、AIは簡単に混乱して誤認識を起こします**。

### 例え話: 「楽譜」を読みたいのに「スピーカーの振動記録」を渡された指揮者
あなたがオーケストラの指揮者だとします。
「ド・ミ・ソの和音が鳴っているか？」を知りたいとき、欲しいのは **「楽譜（どの高さの音が鳴っているか）」** ですよね。
もし目の前に「スピーカーの紙コーンが1ミリ秒ごとに手前に何ミリ動いたか」という数値の羅列（波形）を何万個も渡されたらどうでしょうか？ 天才的な指揮者でも、それがドミソの和音かどうか瞬時には判別できません。

### 致命的な「位相（タイミング）のズレ」問題
同じ人が同じ声で「あー」と言ったとします。
波形の周期が $1\text{ ms}$（1000 Hz）だった場合、**マイクとの距離がたった $17\text{ cm}$（音速で約 $0.5\text{ ms}$ 分）変わるだけで、波の山と谷が完全に逆転（逆位相）** します。

```text
位置Aで録音:  +1.0,  +0.5,   0.0,  -0.5,  -1.0,  -0.5,   0.0,  +0.5 ...
位置Bで録音:  -1.0,  -0.5,   0.0,  +0.5,  +1.0,  +0.5,   0.0,  -0.5 ...
               ↑ 数値がプラスとマイナスで正反対！
```

人間の耳には全く同じ「あー」に聞こえるのに、数値としては正反対のデータになってしまいます。
AIに生の波形をそのまま学習させようとすると、あらゆる立ち位置やタイミングのズレ（位相）のパターンを何百万通りも学習させなければならず、マイコンのような小さなモデルでは到底太刀打ちできません。

**「タイミング（位相）のズレに影響されず、音に含まれる周波数の強さ（楽譜）を取り出す」** こと。これこそが、音響特徴量抽出の最大の目的なのです。

## 2.4 フーリエ変換（FFT）: 波を「周波数の成分」に分解する

### フーリエの基本思想
18世紀の数学者ジョゼフ・フーリエは、驚くべき事実を発見しました。
> **「どんなに複雑にいびつな波であっても、異なる高さ（周波数）の綺麗なサイン波（正弦波）をいくつか足し合わせることで、完全に再現できる」**

```text
[複雑な音の波形] ＝ [100Hzのサイン波] ＋ [300Hzのサイン波] ＋ [1500Hzのサイン波] ＋ ...
```

この「元の波形の中に、どの周波数のサイン波がどれくらいの強さで含まれているか」を計算する数学的手法が **フーリエ変換（Fourier Transform）** です。
コンピュータ上で爆速で計算できるようにしたアルゴリズムを **高速フーリエ変換（FFT: Fast Fourier Transform）** と呼びます。

```text
時間領域 (波形)                       周波数領域 (スペクトル)
  振幅                                  強さ
   │   /\    /\    /\                   │     |
   │  /  \  /  \  /  \    ──( FFT )──▶  │     |         |
   │ /    \/    \/    \                 │  |  |   |     |
   └──────────────────── 時間           └────────────────── 周波数 (Hz)
                                          100 500   2000
```

## 2.5 窓切り（Framing）と窓関数（Windowing）

しかし、音はずっと同じ音が鳴り続けているわけではありません。「ピピッ」「ガタガタ」「助けて」と刻一刻と変化します。
そこで、音声を **短い時間（フレーム）に小さく切り刻んで、コマ送りアニメーションのように順次FFTをかけていく** 手法をとります。これを **短時間フーリエ変換（STFT）** と呼びます。

### なぜ「400サンプル（25 ms）」なのか？
SEROVの固定契約では、窓幅（フレーム長）を **400サンプル**（$16000\text{ Hz}$ で $25\text{ ms}$）に定めています。
- $10\text{ ms}$ 以下だと短すぎて、低い周波数の波（波長が長い音）が1周期分すら入らず、周波数を測れません。
- $100\text{ ms}$ 以上だと長すぎて、音色の素早い変化（子音の発音など）が混ざってぼやけてしまいます。
- **$20 \sim 30\text{ ms}$** は、人間の声や自然界の音が「この一瞬だけは波が定常的（変化しない）とみなせる」最適なスイートスポットなのです。

### なぜ四角く切るとダメなのか？（Periodic Hann窓の秘密）
400サンプルの波形を包丁でブツッと四角く切り取ってそのままFFTにかけると、**切り口の両端（境界）に不自然な断絶（段差）** が生まれます。

```text
矩形窓でブツ切り:
      ┌──────────────────────────┐
──────┘                          └──────
       ↑ 両端に急峻な絶壁ができる！
```

数学的に、急峻な絶壁（不連続点）は「無限の高周波ノイズ」を発生させます。
元の音には存在しなかったはずの偽の高周波成分が周囲の周波数帯にジャバジャバと漏れ出してしまう現象を **周波数漏洩（Spectral Leakage）** と呼びます。

これを防ぐため、両端を滑らかにゼロに落とし、中央をそのまま通す **窓関数（Window Function）** を掛け算します。
SEROVでは、信号処理の標準である **Periodic Hann（ハン）窓** を使用しています。

```text
Periodic Hann窓:
           ╭──────────────╮
──────────╯                ╰──────────
       両端がなめらかにゼロに収束する
```

$$\text{Hann}[n] = 0.5 - 0.5 \cos\left(\frac{2\pi n}{400}\right) \quad (n = 0, 1, \dots, 399)$$

Python参照実装（`features.py`）の該当コードを見てみましょう：
```python
def periodic_hann(dtype: np.dtype = np.dtype(np.float64)) -> np.ndarray:
    """400点periodic Hann係数を返す。"""
    sample = np.arange(WINDOW_SAMPLES, dtype=np.float64)
    return 0.5 - (0.5 * np.cos((2.0 * np.pi * sample) / WINDOW_SAMPLES))
```
このように、綺麗なコサインカーブで両端をそっとゼロに落としてあげることで、余計なノイズを一切出さずに綺麗な周波数スペクトルを抽出できるのです。

## 2.6 まとめ

- 音の正体は空気の圧力振動。SEROVはサンプリング定理に基づき、探査に必要な8kHzまでの音を捉えるため **16,000 Hz** で集音している。
- 生の波形はマイクとの距離（位相のズレ）で値が激変するため、そのままではAIが音を正しく認識できない。
- **高速フーリエ変換（FFT）** を使うことで、波形を「どんな高さ（周波数）の音がどれくらい鳴っているか」の成分に分解できる。
- 音の変化を追うため、音声を **400サンプル（25ms）** ずつ切り出し、端っこのノイズ（周波数漏洩）を防ぐために **Periodic Hann窓** を掛けてからFFTを実行する。

しかし、FFTで分解した周波数成分はまだ257個もの数値があります。
次章では、これをさらに人間の耳の仕組みを使ってギュッと32個に圧縮する **「Log-Melスペクトログラム」** の魔術を学びます！
