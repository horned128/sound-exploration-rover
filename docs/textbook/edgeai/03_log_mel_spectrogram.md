# 第3章: 人間の耳を模倣する「Log-Mel特徴量」の仕組み

前章では、マイクで拾った音を400サンプル（25ms）ずつ切り取り、窓関数（Hann窓）を掛けて512点FFTを実行することで、**257個の周波数成分（パワースペクトル）** を取り出すところまで学びました。

しかし、257個の数値が毎秒100回（100 fps）も流れてくると、マイコンの小さなメモリと処理能力ではまだ重すぎます。
そこで本章では、**人間の耳（蝸牛）の構造を模倣して、データを257個から「32個」へと一気に約1/8に圧縮する「Log-Mel特徴量」** の仕組みを解き明かします。

---

## 3.1 人間の耳は「高音に対して大雑把」である

### 人間の聴覚の不思議（メル尺度: Mel Scale）
人間の耳は、機械の測定器とは全く異なる面白い特性を持っています。

```text
[低い音]  100 Hz  と  200 Hz  の差 ──▶ 「全然違う！ 1オクターブも高い！」（超敏感）
[高い音] 7000 Hz  と 7100 Hz  の差 ──▶ 「どっちも同じ高音のシャーという音だ」（超鈍感）
```

どちらも物理的な周波数の差は「$+100\text{ Hz}$」で全く同じです。
しかし、人間の耳（耳の奥にある音を感じる器官「蝸牛: かぎゅう」）は、**「低い周波数の違いには極めて敏感だが、高い周波数の違いにはとても鈍感」** に作られています。

1937年、音響心理学者のスティーブンスらは、人間のこの主観的な音の高さの感覚を測定し、**「メル尺度（Mel Scale）」** という単位を定義しました。
「物理的な周波数（Hz）」を「人間の感覚（Mel）」に変換する式（HTK形式）は次の通りです：

$$\text{Mel}(f) = 2595 \times \log_{10}\left(1 + \frac{f}{700}\right)$$

```text
周波数 (Hz)       0   500   1000        3000                 8000
                  │────│─────│───────────│────────────────────│
メル尺度 (Mel)    0   500   1000        1800                 2800
                  │──────│──────│────────│─────────│──────────│
                  [ 低音は広げる ]          [ 高音はギュッと縮める ]
```

## 3.2 32個の三角メルフィルタバンク（Mel Filterbank）

### 257個の数値を「32個の三角のザル」で受け止める
512点FFTから得られた257個の周波数成分（$0\text{ Hz} \sim 8000\text{ Hz}$、刻み幅 $31.25\text{ Hz}$）を、そのままAIに渡す必要はありません。人間の耳と同じように、**「低音は細かく、高音は大雑把にまとめる」** のです。

そこで使われるのが、32個の二等辺三角形の形をした **「三角メルフィルタバンク」** です。

```text
重み
 1.0 ─┐   /\  /\   /\    /\     /\       /\         /\           /\
      │  /  \/  \ /  \  /  \   /  \     /  \       /  \         /  \
 0.0 ─┴─/───/\───X────\/────\─/────\───/────\─────/────\───────/────\──
       125Hz     低音域 (細い三角)              高音域 (幅の広い三角)    8000Hz
       [ch 0]    [ch 1]  [ch 2] ...            [ch 30]       [ch 31]
```

### 三角フィルタの働き
1. **低音域（125 Hz 〜 1000 Hz付近）**:
   - 三角形の幅がとても狭く、隣り合う三角形同士の間隔も密になっています。
   - FFTのビン（bin）が数個ずつ丁寧にまとめられ、微妙な音程の違いを逃しません。
2. **高音域（4000 Hz 〜 8000 Hz付近）**:
   - 三角形の幅がとても広く、ドサッと数十個のFFTビンをまとめて足し合わせます。
   - 「だいたい高い音が鳴っているな」というエネルギーの塊として大雑把に捉えます。

各チャンネル $m$（$0 \le m < 32$）のエネルギー $E_m$ は、FFTパワースペクトル $P[k]$ に三角フィルタの重み $W_m[k]$ を掛けて足し算するだけで計算できます：

$$E_m = \sum_{k=0}^{256} W_m[k] \cdot P[k]$$

これによって、**257個あった周波数の数値が、たったの「32個の数値」にギュッと凝縮** されました！

## 3.3 なぜ「対数（Log）」をとるのか？

### 蚊の羽音から飛行機の爆音まで（莫大なダイナミックレンジ）
音のエネルギー（強さ）は、静かな部屋のささやき声と、目の前で鳴るクラクションで、平気で **$1,000,000$ 倍（100万倍）以上** 変化します。
この生エネルギーの数値をそのままAIに入力すると、次のような問題が起きます。
- 小さな音が $0.000001$、大きな音が $1000.0$ となり、AIのニューラルネットワークの計算が大きな音に引っ張られて発散してしまう。
- 人間の耳自身、音のエネルギーが10倍になって初めて「音量が2倍になった」と感じる（ウェーバー・フェヒナーの法則）。

そこで、エネルギーの **自然対数（Log）** をとります。

$$\text{LogEnergy}_m = \ln\left(\max(E_m, 10^{-12})\right)$$

- $10^{-12}$ はアンダーフロー防止の下限クリップです（無音のときに $\ln(0) = -\infty$ になってプログラムがクラッシュするのを防ぎます）。
- 対数をとることで、$1$ から $1,000,000$ までの莫大な数値が、**約 $0 \sim 13.8$ という非常に扱いやすいコンパクトな範囲** にギュッと収まります。これが「**Log-Mel**」と呼ばれる所以です。

## 3.4 フレーム平均減算（Level Normalization）: 音量に騙されない

### 音源が遠いと音が小さく、近いと大きくなる問題
ローバーが音源（救助を呼ぶ声など）を探して走行しているとき、最初は遠くにいるため音は小さく、近づくにつれて音はどんどん大きくなります。
もしAIが「音の絶対的な大きさ（数値の大きさ）」を見ていたらどうなるでしょうか？
- 遠くで鳴った「助けて」：小さな数値
- 近くで鳴った「モータ音」：大きな数値
AIは「音の大きさ」に惑わされて、同じ「助けて」という声でも距離によって違う音だと誤認してしまいます。

### 平均値を引いて「音色」だけを抽出する
そこでSEROVでは、各フレーム（32帯域）ごとに、**そのフレームの平均対数エネルギーを計算し、全帯域から引き算** しています。

$$\text{Mean} = \frac{1}{32} \sum_{m=0}^{31} \text{LogEnergy}_m$$
$$\text{Normalized}_m = \text{LogEnergy}_m - \text{Mean}$$

```text
[未正規化 (遠くの音)]   3.1,  3.5,  2.8,  4.2 ... (全体的に低い)
[未正規化 (近くの音)]   8.1,  8.5,  7.8,  9.2 ... (全体的に高い)
                           ↓ 各フレームの平均値を引く
[正規化後 (遠くの音)]  -0.3, +0.1, -0.6, +0.8 ...
[正規化後 (近くの音)]  -0.3, +0.1, -0.6, +0.8 ... ★ 全く同じ数値の並び（音色のパターン）になった！
```

この「フレーム平均減算」という極めてシンプルな引き算のおかげで、**ローバーは音源との距離に関係なく、純粋な「音色（音の種類）」だけを安定して識別できる** のです。

## 3.5 実機コードとの対応（Python vs C言語）

この美しいDSP処理が、実際にどうコードになっているか見てみましょう。

### Python参照実装（`software/acoustic-trainer/features.py`）
```python
# 1. 32帯域のMelフィルタバンク適用
mel_energies = np.dot(mel_fb, power_spectrum)

# 2. 自然対数変換 (下限1e-12)
log_mel = np.log(np.maximum(mel_energies, 1e-12))

# 3. フレーム平均減算
mean_energy = np.mean(log_mel)
normalized_log_mel = log_mel - mean_energy
```

### ESP32-S3 C言語ファームウェア（`firmware/esp32s3/src/log_mel_extractor.c`）
```c
/* 1. 32帯域のMelエネルギー積算 */
for (uint32_t bin = 0; bin < 32; bin++) {
    float energy = 0.0f;
    for (uint32_t k = filter_start[bin]; k <= filter_end[bin]; k++) {
        energy += power_spectrum[k] * filter_weights[bin][k];
    }
    if (energy < 1.0e-12f) energy = 1.0e-12f;
    log_mel[bin] = logf(energy); /* 2. 自然対数 */
    sum_log_mel += log_mel[bin];
}

/* 3. フレーム平均減算 */
float const mean = sum_log_mel / 32.0f;
for (uint32_t bin = 0; bin < 32; bin++) {
    normalized[bin] = log_mel[bin] - mean;
}
```
驚くほどシンプルで、美しい対応関係になっていることがわかりますね！

## 3.6 まとめ

- 人間の耳（蝸牛）は低音に敏感で高音に鈍感である（**メル尺度**）。
- 257個のFFT成分を **32個の三角メルフィルタバンク** で足し合わせることで、データ量を一気に約1/8に圧縮する。
- 莫大な音のエネルギー差を扱いやすくするため、**自然対数（Log）** で圧縮する。
- 音源との距離（音量の大小）に惑わされず、純粋な「音色」だけを取り出すため、**フレーム平均減算** を行う。

これで、1コマあたり「32個の浮動小数点数（float）」が得られました。
しかし、マイコンにとっては `float`（32ビット浮動小数点）のまま計算するのもまだ贅沢です。
次章では、これをさらに **たった1バイトの整数（int8）に変換する「量子化の魔術」** を学びます！
